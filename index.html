STEP-BY-STEP CONTRIBUTION WORKFLOW

Fix Blueprint

Follow this verified engineering roadmap to investigate, reproduce, implement, and open a clean pull request for your selected issue.

STAGE A

1. Verify Availability & Claim the Task

Before writing code, inspect recent comments on GitHub to make sure another contributor isn't actively working on it. Claiming prevents duplicate effort.

Maintainer Etiquette Tip:

Leave a friendly comment expressing your intent to work on the task. Never demand assignment; wait for maintainer confirmation or start local investigation immediately.

Maintainer Comment Template (Editable):
STAGE B

2. Fork Repository & Create Feature Branch

Fork the project to your GitHub account. Clone your fork locally and configure the original repository as an upstream remote so you can stay in sync.

Commands below update automatically with your fork URL.
1. Clone your fork: 
git clone https://github.com/contributor/repo.git && cd repo
2. Add upstream remote (stays synced with main project): 
git remote add upstream https://github.com/owner/repo.git
3. Create a dedicated feature branch: 
git switch -c fix/starter-contribution
STAGE C

3. Locate Code & Reproduce Problem

Identify the exact files involved. Inspect the implementation and confirm the bug or missing functionality on your machine before making changes.

Investigation Checklist:
  • Search for unique error strings, function names, or component tags in your IDE.
  • Check if reproduction steps in the issue description succeed on your clean branch.
  • Verify whether the issue has existing unit tests that currently fail or need updating.
STAGE D

4. Run Tests & Linters

Run the test suite locally before and after editing code. Tests are suggested based on repository files and detected toolchains.

Interpreting Test Failures:

If existing tests fail before you write code, check the repository's CONTRIBUTING.md for setup instructions or missing dependencies (e.g. Node version, Docker daemon, environment variables).

STAGE E

5. Implement, Review Diff & Open PR

Keep your change minimal and focused solely on the issue. Review your diff with git diff, commit with a descriptive message, push to your fork, and open the Pull Request.

1. Inspect your changes: 
git diff && git status
2. Commit with conventional commit format: 
git commit -am "fix: resolve issue description (closes #1)"
3. Push to your fork (safe destination): 
git push -u origin fix/starter-contribution
Open PR on GitHub
